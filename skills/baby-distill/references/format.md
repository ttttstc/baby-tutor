# baby-tutor 条目格式规范 v1

> 唯一蒸馏标准。所有蒸馏 subagent 必须遵守本文。变更需同步改本文件并升版本号。

## 一、条目文件约定

- 路径：`references/<分类>/<id>.md`，一条方法论一个文件
- **切条粒度 = 问题粒度**：一条 = **一个家长会独立问出来的具体问题**（不是一章一条，也不是一本书一条）。判据：「这个问题，家长会不会单独问一次？」会 → 单独一条。允许多条回答同一个大主题下的不同子问题。
- 长度：**正文（去 frontmatter）2500-6000 中文字符，中位数瞄准 3500**。问题粒度比方法论粒度窄——窄问题各节可短；**上限 7000**（超了说明把整本书塞进了一条），**下限 2000**（低了说明没讲透）。内容特别丰富的宽主题条目（如总纲）可到 8000。
- 一本书产多少条**不设上限**：内容丰富的书（育儿百科、睡眠全书、教科书、图解系列）可 **40-80 条**；单主题小册 5-15 条。**宁多勿少——目标是把书上的知识点覆盖到，漏一个具体问题，家长就掉进缝隙**。**不做跨书去重**（见 §七.6）、**不做月龄子集截断**（见 §七.7）。
- 语言：中文，书名/术语首次出现附英文原文

## 二、frontmatter 字段（15 个）

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | ✅ | `<分类前缀>-<方法/作者>-<slug>`，如 `sooth-karp-5s`、`slp-ferber-graduated`、`cui-fever-threshold`、`mon-mobile-area` |
| `title` | ✅ | 一句话判断式标题——说结论不说主题（"被打断一次要二十分钟才回神"式，不是"深度工作简介"式） |
| `category` | ✅ | 十分类之一（见第五节） |
| `age_range` | ✅ | BabyForge 15 段分期 id 数组（见第六节）。全年龄适用写全部；超 0-6 岁截到 0-6 |
| `also_in` | — | 副分类数组（正文照 work-tutor 惯例：主分类目录放全文，副分类只挂索引行） |
| `evidence` | ✅ | tier-1 / tier-2 / tier-3 / tier-4（定义见第四节） |
| `conflicts_with` | — | 对立方法条目 id 数组（睡眠训练、喂养流派等争议主题必填） |
| `red_flags` | ✅ | 本主题就医红旗关键词数组（触发「先说安全」节用；无则 `[]`） |
| `extraction` | ✅ | `"S1: <书名> (epub) c04-c08"` 或 `"S2: healthychildren.org Crying & Colic, 2026-10-03 校准"`。**没有此字段 = 不合格** |
| `problem` | ✅ | 用户会怎么问（最典型的一句原话式问法） |
| `problem_variants` | ✅ | 3-5 个变体问法（含口语/老人转述版） |
| `signals` | ✅ | 3-6 条处境信号（描述用户的错误认知状态或典型处境） |
| `tradeoffs` | ✅ | 2-4 条代价（时间/金钱/关系/短期痛苦） |
| `sources` | ✅ | 来源数组：type（理论/指南/研究）+ ref（书名+年份+页码或章节 / 指南 URL） |
| `note` | — | 与相邻条目的区分说明（防混淆，work-tutor 惯例） |

## 三、正文 13 节（work-tutor 11 节 + 育儿新增 2 节）

节名固定，不得自创。顺序：

| # | 节名 | 来源 | 内容要求 |
|---|---|---|---|
| 1 | `## 解决的问题` | 继承 | problem 展开 2-3 段，场景代入，让读者对号入座 |
| 2 | `## 核心判断` | 继承 | 1-2 句，敢下判断，说用户没说出来的那层 |
| 3 | `## 机制` | 继承 | 为什么有效：生理/发展/心理因果链。**证据强度随行标注**（"此机制有 RCT 支持"/"这是作者的理论假说"） |
| 4 | `## 诊断信号` | 继承 | 什么情况用这条；**开头一句月龄判断**（适用窗口+何时递减/失效） |
| 5 | `## 正常范围与个体差异` | **⭐新增** | 该现象的月龄正常区间数据对照。**只做科学对照，不做安抚**——写"90% 婴儿在 X 月达成"这种数据，不写"别担心每个宝宝都不一样"这种安慰 |
| 6 | `## 实操方法` | 继承 | 步骤化 1-7 步，每步可执行、能回答"今晚就做什么" |
| 7 | `## 备选计策` | 继承 | 2-4 条替代法，**每条标注适用家庭**（如"能接受少量哭声的家庭"/"父母轮流值班的家庭"） |
| 8 | `## 决策规则` | 继承 | **判断标准三件**：怎么算有效（可观察指标）/ 坚持多久再评估 / 出现什么信号换下一条 |
| 9 | `## 反模式` | 继承 | 常见错误做法+各自后果（含流传广的错误做法） |
| 10 | `## 边界` | 继承 | 适用前提/不成立的条件（含月龄出界、家庭条件限制） |
| 11 | `## 就医红线` | **⭐新增** | 本主题何时必须就医：症状+阈值，写死数字（如"3 月龄内发热 ≥38℃ 直接送医"）。来源标 tier-1 |
| 12 | `## 代价与风险提示` | 继承 | 主动选这条路要付的账 |
| 13 | `## 来源` | 继承 | 书目（含页码/章节）+ 指南 URL + 校准日期 |

## 四、证据分级（evidence 字段取值）

| tier | 定义 | 例 |
|---|---|---|
| `tier-1` | 机构现行指南/立场文件 | AAP 安全睡眠政策、WHO 辅食指南 2023、卫健委照护指南 2022 |
| `tier-2` | 同行评议研究直接支持的方法（RCT/系统综述/元分析） | 渐进消退法（多篇 RCT）、1-2-3 Magic（2014 澳洲 RCT） |
| `tier-3` | 具专业背景作者的专著方法论（无直接 RCT 但有理论+临床基础） | 5S 安抚法、DOR 喂养分工、蒙氏大部分实践 |
| `tier-4` | 流行理念：影响力大但实证弱或方法学受质疑 | Wonder Weeks 预测、敏感期绝对化表述、3000 万词汇差距原始数字 |

规则：tier 标**本条目核心方法**的层级；正文「机制」里对具体主张可分别标注不同强度。书与 tier-1 指南冲突时，正文以指南为准并标注分歧。

## 七、蒸馏纪律（鸡汤过滤器，硬标准）

1. **四件套缺一不收录**：机制（标证据强度）+ 步骤化实操 + 判断标准（怎么算有效/何时换法）+ 红线。缺任何一件的主题不立条目
2. **禁止提取**：纯情绪安慰、理念宣言、无操作性内容。「正常范围」节只做数据对照
3. **只用实文**：内容必须来自 S1 实文章节或 S2 官方页原文。**禁止凭训练记忆补写书中内容**——书上没有的判断，宁可不写，或明确标注"（蒸馏者注：非本书内容，来自 <来源>）"
4. **数字溯源**：所有阈值/时长/剂量数字必须来自原文或官方校准源，标校准日期
5. **一书多主题，覆盖度优先**：按"家长会独立问出的具体问题"切条，**不设上限**。目标不是"提炼精华"，是**覆盖书上的知识点**——逐章过、每个可独立提问的点都立条。**一本 0-6 岁综合大书（育儿百科/教科书/图解系列）可出 40-80 条**，单主题小册 5-15 条。疑问题（"宝宝X怎么办"）、判断题（"怎么判断X"）、知识题（"X是什么样/为什么"）都算。
6. **允许主题重叠，禁止跨书去重**：多本书讲同一主题（8 本睡眠书都讲夜醒）时，**各立各的条目**，用 `conflicts_with` / `note` 互相指路——**绝不为"去重/取独有内容"压缩一本书**。覆盖密度压倒去重。一本书的产出只由它自己的内容量决定，不因别人先蒸了而被砍。
7. **全 0-6 岁范围，不设月龄子集**：除非书本身就是单月龄专题，**不得把一本 0-6 岁的书限制在某个子区间（如"只蒸 0-1 岁"）**。整本按 0-6 岁处理。
8. **争议处理**：对立方法各立条目，`conflicts_with` 互引；蒸馏 A 派时不得贬低 B 派，各说各的证据
9. **保留原书场景实例**：条目自带的场景实例照抄比编好（work-tutor 惯例）
10. **触发字段与正文同等重要**：problem 必须是父母深夜原话式（一句话、带情绪、具体，禁止主题词式）；variants 覆盖口语版/焦灼版/老人转述版/自责版；signals 描述用户可自查的处境现象。**触发字段弱 = 条目白写**
11. **方法论说清楚**：核心是"这个方法是什么、怎么一步步做、怎么判断对不对"——具体策略优先于背景知识。书的背景叙事、章节铺陈、作者故事不蒸馏（案例数字除外）

## 八、源质量门（蒸馏前必查）

| 级 | 定义 | 处置 |
|---|---|---|
| A | 原书全本文字版（epub/mobi/azw3/PDF 文字层） | 通过，正常蒸馏 |
| B | 部分章节实文 | 只蒸有实文部分，extraction 标注范围 |
| C | 读书笔记/书评/摘要/二手解读 | **拒绝** |
| D | OCR 乱码/残缺/模糊扫描 | **拒绝** |

### 八之二、视觉蒸馏协议（PDF 扫描件专用，质量红线更高）

**触发**：源为扫描图 PDF（无可靠文字层）或文字层 OCR 质量差。实测本批 PDF 的文字层多不可靠（中文错字/英文词粘连），一律走视觉逐页读取。

**铁律（比 epub 蒸馏更严，因为看图比读文本更易出错）**：
1. **逐页视觉读**（Read 工具 pages 参数，20 页/次）。**只看图、不靠记忆补全**。
2. **看不清就整段舍弃**：任何字/数字/表格模糊到不能 100% 确认 → 该点不写进条目，绝不"猜一个大概"。宁可条目短，不可错。
3. **每个事实标注源页码**：条目 body 的关键数字/引用旁标 `（pXX）`，extraction 标 `S1-PDF-视觉 <书名> pXX-XX`。
4. **双读校验（强制）**：蒸馏完成后，**派一个独立 agent 回读同批源页**，逐条核对每个数字/引用/结论是否与图一致。不一致 → 修正或删除该条。**未过校验的条目不入库**。
5. **医学/安全数字再叠加官方指南交叉核对**（第二道）。
6. **逻辑自洽**：机制→实操→判断标准必须连贯；发现条目内部逻辑不通 → 重写或删除。
7. **宁缺毋滥**：一本扫描书蒸出的条目数少于 epub 是正常的——因为看不准的部分被舍弃了，这是对的。

### 八之三、入库前质检（所有来源通用，PDF 尤为关键）

任何新条目入库前过四问，任一为否就不入：
1. **能溯源吗**？extraction 指向具体书名+章节/页码。
2. **数字对吗**？关键数字回源核对 + 官方指南交叉（医学类必须）。
3. **逻辑通吗**？机制支持方法，方法有判断标准，无自相矛盾。
4. **和库里打架吗**？同主题若有对立流派，正反都标 conflicts_with 并按「矛盾消解」处理。

## 九、索引（`references/_index/<分类>.md`）

**由主会话的重建脚本统一生成，蒸馏代理不写索引。** 生成规则（主会话执行 `python skills/baby-distill/scripts/rebuild_index.py` 或等效 inline 脚本）：

```markdown
| id | tier | 月龄 | 判断 | 用户会怎么问 | signals |
|---|---|---|---|---|---|
| `sooth-karp-5s` | tier-3 | 0-4月 | <title> | <problem> | <signals 前4条各截28字> |
```

- 月龄列由 age_range 的 15 段 id 自动翻译成人话区间
- 副分类挂靠行自动追加（`⤴副` 标记 + "主分类在别处"提示）
- 表头注释：先比「用户会怎么问」逐字命中，再比「判断」，signals 只作辅助（≥2 条才算）

```markdown
## <书名> 蒸馏结果
- 源：<文件名>，质量门 <A/B>，extraction 范围
- 产出 N 条：<id>（<分类>，<tier>，<月龄>）× N
- 索引：已写入 _index/<分类>.md
- 未覆盖主题：<书中 X 主题因 <四件套缺项/超出 0-6 月/PDF 限制> 未立条>
```
