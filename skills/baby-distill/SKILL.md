# baby-distill · 育儿书籍蒸馏 skill

## 一、这个 skill 干什么

把一本电子书（epub/mobi/azw3 文字版，**PDF 暂不蒸馏**）或一组官方网页，蒸馏成 baby-tutor 知识库的标准条目 + 索引行。

**不是**逐章摘要，**不是**读书笔记，**不是**把书抄薄。是按格式规范切出"能独立回答一个育儿问题的方法论单元"。

## 二、开工前检查（缺一不蒸馏）

1. **读 [references/format.md](references/format.md)**——它是唯一标准，本 SKILL.md 只是流程
2. **质量门**：验证源文件过 A/B 级（全本文字版/部分实文）。epub/mobi/azw3 直接过门；验证方法：解包后抽 3 个章节文件确认文字完整。C/D 级（笔记/乱码）直接终止并报告
3. **月龄初判**：扫一遍目录（epub 的 opf/ncx 或章节文件名），划出 0-6 月相关章节范围——**只蒸馏这个范围**，其余章节在汇报里记"未覆盖+原因"
4. **无月龄概念的书**（如"父母自身"类）：跳过月龄初判，按主题相关性判断

## 三、蒸馏流程（六步）

```
1 解包 → 2 读相关章节原文 → 3 切条（按方法论密度）→
4 写条目（15 字段 frontmatter + 13 节正文，全按 format.md）→
5 写索引行 → 6 汇报（按 format.md 第十节格式）
```

### 1. 解包
```bash
# epub：本质是 zip
cd /tmp && rm -rf <workdir> && mkdir <workdir> && cd <workdir> \
  && cp "<书路径>" book.epub && unzip -q book.epub
# 章节文件在 OEBPS/ 或根目录，.htm/.xhtml/.html
# mobi/azw3：先转 epub（calibre 的 ebook-convert 若可用），失败则报告"格式不可处理"
```

### 2. 读原文
用 Read/Grep 直接读解包后的章节文件。**只读 0-6 月相关章节**。章节文件是 HTML，内容可读，忽略标签。长章节分段读。

### 3. 切条（问题粒度）
- **判据**：一个条目 = **一个家长会独立问出来的具体问题**。「这个问题，家长会不会单独问一次？」会 → 单独一条。
- **不设上限**：一本内容丰富的书（育儿百科/睡眠全书/教科书）可切 **15-40 条**；单主题小册 3-8 条。漏一个具体问题，家长就掉进条目缝隙——**宁多勿少**。
- **允许重叠**：多本书讲同一主题时各立各的，用 `conflicts_with`/`note` 互相指路，**不要为"去重"把一本书榨成 2 条**。
- 每条对照**四件套**初判可立性：机制+实操+判断标准+红线——只有理念没有操作的主题不立条。
- 例子：一本睡眠书不该只出"N 条睡眠方法论"，而应出「前半夜频繁醒」「后半夜早醒」「小睡 30 分钟就醒」「并觉期反复醒」「奶睡依赖」「睡眠倒退」「夜惊 vs 噩梦」等一条一问题的密集条目。

### 4. 写条目
- 全部字段与节名**严格照 format.md**，一个字不改
- **只用实文**：内容必须来自已读章节原文。书上没有的判断宁可不写，或标"（蒸馏者注：非本书内容，来自 <来源>）"
- 医学/安全数字：原文数字照录，并核对本仓库 `电子书/官方指南/` 下对应官方文件（WHO/卫健委/CDC/AAP），不一致时以官方为准并在「来源」注明分歧
- **鸡汤过滤器**：纯安慰、理念宣言、"你已经做得很好了"式内容一律不提取
- 落盘：`D:\AI\workspace\baby-tutor\references\<分类>\<id>.md`

### 5. 索引——不写！（并行安全纪律）

**蒸馏 subagent 一律不碰 `_index/` 目录。** 索引由主会话在每波蒸馏完成后统一跑重建脚本生成（从条目 frontmatter 自动提取，含副分类挂靠行）。历史上并行代理各写索引曾互相覆盖丢行——此纪律即由此而来。

### 6. 汇报
按 format.md 第十节格式，在会话里报告：源+质量门等级、产出条目清单、未覆盖主题及原因。

### 格式管线（解包方式）
- **epub**：`unzip -q book.epub` 直接解
- **mobi**：python 库 `mobi.extract(<file>)` → 产出单 html 文件
- **azw3**：`mobi.extract()` 产出的文件实为 epub 字节流（PK 头），写成 .epub 再 unzip；或 azw3 本身部分可直接 unzip（先试 zipfile）

## 四、并行蒸馏（多书时）

多本书并行，**一书一 subagent**（大书可再拆分给嵌套 subagent）。给每个 subagent 的 prompt 模板：

```
蒸馏《<书名>》。源文件：D:\AI\workspace\电子书\<文件名>（质量门 A 级，已验证）。
1. 先 Read D:\AI\workspace\baby-tutor\skills\baby-distill\references\format.md 并严格遵守
2. 再 Read 本 SKILL.md 的「四之二 触发字段质量标准」
3. **先去重**：grep 现有同名书条目 + 读该分类 _index，已覆盖的问题跳过
4. 解包读到 /tmp/<slug>，按**问题粒度**切条（一条=一个家长会独立问的具体问题，**不设上限**）
5. 写条目到 D:\AI\workspace\baby-tutor\references\<分类>\（id 前缀按 format.md，与现有区分）
6. **不写索引文件**（主会话统一重建）
7. 按 format.md 第十节汇报
```

**两条运维纪律（实测踩过）**：
1. **并发上限 20 个 subagent**（`CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS`）：一次派超过 20 会报 "Concurrent subagent limit reached"。按每批 ≤20 规划波次，失败的稍后补派。
2. **shell 环境可能坏**（PATH 缺 git-bash 的 `/usr/bin`，`ls`/`grep`/`python` 都找不到）：prompt 里提醒 subagent 命令前先 `export PATH="/d/soft/Git/usr/bin:$PATH"`，python 用绝对路径 `D:/soft/anaconda/python.exe`。

（prompt 里的分类由主会话根据书的主题预指定，subagent 可按实际内容调整并说明。）

## 四之二、触发字段质量标准（与正文同等重要）

**用户问法和条目对不上 = 条目白写。** 触发字段（problem / problem_variants / signals）决定检索命中率，蒸馏时与正文同等工作量对待：

1. **problem** = 父母深夜会打出的那句原话，一句话、带情绪、具体。禁止主题词式（❌"新生儿哭闹问题"，✅"宝宝一哭就是几个小时，全套做完还在哭，我快崩溃了"）
2. **problem_variants** 3-5 个必须覆盖不同问法角度：口语版（"怎么哄都不睡"）、焦灼版（"是不是肠绞痛要不要去医院"）、老人转述版（"婆婆说让宝宝哭哭没关系"）、自责版（"是不是我奶不够"）
3. **signals** 描述处境不描述理论——用户能自查到的现象（"喂完拍完还在哭"✅），不是条目内部概念（❌"镇静反射未被触发"）
4. **写完自查**：拿 problem_variants 每条默想"用户真这么说，索引双通道能命中吗"——命不中就重写
5. **一个主题一个入口**：同一方法论不要拆成两个模糊条目；两个不同问题不要挤进一个条目（如"哄不住的哭"和"一放就醒"是两条）

## 四之三、双源核对与医学数字纪律

- 医学/安全数字（阈值/时长/剂量）：原文照录后，核对本仓库 `D:\AI\workspace\电子书\官方指南\` 下对应官方文件（WHO/卫健委/CDC/AAP），不一致时以官方为准并在「来源」注明分歧
- 官方指南类蒸馏（S2）产出 00 类安全条目时，条目 red_flags 直接嵌官方阈值

## 五、批次验收（每批蒸馏完成后必跑，机械检查）

**跑脚本，不靠肉眼**（本批曾真实踩坑：24 条缺闭合 `---` 或 H1、7 条 CRLF）：

```bash
# 1. 索引重建（代理不写索引，主会话统一生成）
python skills/baby-distill/scripts/rebuild_index.py
# 2. 机械验收（frontmatter/H1/CRLF/字段/13节/月龄id/conflicts/索引覆盖）
python skills/baby-distill/scripts/validate_entries.py
```

脚本退出码非 0 = 有硬伤，逐项修复后重跑至通过。**另需人工抽查**：
1. 随机抽 3-5 条，对照四件套 + extraction 页码/章节与源文件核对（防凭记忆补写）
2. 风格检查：无鸡汤段落；「正常范围」无"别担心"式语言；判断标准可操作
3. 问题分级：硬伤（四件套缺失/extraction 造假/医学数字无来源）→ 修复；软伤（表达啰嗦/signals 弱）→ 列待用户决定

## 五之二、成熟库的检索层维护（库里 >300 条后）

问题粒度会把库迅速做大（>300 条时单分类索引可达 80+ 行）。消费端（baby-tutor）每次只读**命中分类**的索引，仍可控；但需注意：

1. **索引瘦身预案**（单分类 >50 行时启用）：`rebuild_index.py` 输出可去掉 `signals` 列（signals 只在条目 frontmatter 保留），单行从 6 列减到 5 列，索引体积省约 40%。改一处 `rebuild_index.py` 的表头即可。
2. **同主题多条目共存**（问题粒度 + 允许重叠的必然结果）：同一问题可能有 3-4 本书的条目（如"安全座椅"有 aap-safe-carseat / aap-ybfy-car-seat / safe-jana-car-seat）。索引靠「用户会怎么问」逐字命中选最强；`note` 字段应互相指路。这是**设计内**的，不是重复 bug。
3. **id 前缀一致性**：理想是"分类前缀-作者-slug"，但并行蒸馏常出现 `aap-safe-*`（作者在前）等变体。**不强求统一**——只要 id 唯一、能进索引即可；统一化是可选清理，收益低于风险，不必做。

## 六、纪律

- **不蒸馏 PDF**（待用户解除）
- **不用盗版判断标准放松质量门**：用户自筹的源也照 A/B/C/D 分级，C/D 拒收——与来源合法性是两回事
- **不代跑 baby-tutor**：蒸馏出的条目如何被使用是 baby-tutor skill 的职责
- **医学数字双源核对**：书 vs 官方指南不一致时，以指南为准+标注分歧
- **批次必过机械验收**：validate_entries.py 通过才收工
- **并发 ≤20 subagent**：超限报错；shell 坏了先 `export PATH="/d/soft/Git/usr/bin:$PATH"`
- 汇报时如实报未覆盖主题，不为好看凑条数
